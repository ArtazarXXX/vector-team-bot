## 📌 О проекте

Школьники хотят побеждать в конкурсах и хакатонах, но тонут в бюрократии регламентов и боятся «начинать с нуля» при страте работы над проектами. У учителей и наставников («IT-куб», «Кванториум», школы) не хватает времени на индивидуальное ведение десятков подопечных.

**«ВЕКТОР»** решает эту проблему прямо внутри школьного мессенджера **Сферум (MAX)**:
1. 🧭 **«Умный навигатор»** — структурированный реестр из ключевых верифицированных олимпиад и всероссийских хакатонов сезона 2026/2027 (НТО, «Большие вызовы» Сириуса, Всерос, хакатоны IT-кубов, Кванториумов и Сферума). Поддерживает фильтрацию по направлениям, классам (7–11), бонусам к ЕГЭ/БВИ и персональный трекер «Мои дедлайны».
2. 💡 **«ИИ-Ко-Пилот»** — диалоговый наставник-методист, помогающий декомпозировать идею на цель, задачи и научную гипотезу по канонам ФГОС.
3. 🎙️ **«Репетиция защиты»** — симулятор каверзных вопросов жюри хакатона с методическим разбором ответов.
4. 📋 **«Паспорт проекта & Синхронизация»** — сборка чистового паспорта проекта, готового для отправки учителю в чат Сферума в один клик.
5. ⭐ **«Мои дедлайны»** — персональный трекер закладок с обратным отсчетом дней до окончания регистрации.

## 🛠 Технологический стек

* **Платформа:** Мессенджер MAX (официальный Bot API)
* **SDK:** `@maxhub/max-bot-api` (TypeScript, Node.js 22)
* **База данных:** SQLite (`better-sqlite3`, WAL-mode, персистентное хранилище в `data/vector.db`)
* **Автоматический парсер:** Сервис парсинга открытых RSS-лент и агрегаторов (`fast-xml-parser`) с автоматическим выделением дедлайнов, направлений и целевых классов
* **Режим работы:** Long Polling (локально и в Docker без необходимости белого IP)
* **LLM-слой:** OpenAI-совместимый интерфейс интеллектуальных языковых моделей с каскадным отказоустойчивым Fallback-режимом
* **Контейнеризация:** Docker, Docker Compose (мультистейдж сборка на `node:22-alpine` с монтированием тома данных)
* **Библиотеки и версионирование:** Полный список зависимостей с описанием и версиями приведен в [DEPENDENCIES.md](DEPENDENCIES.md) и [requirements.txt](requirements.txt)

## 🚀 Запуск через Docker

Убедитесь, что установлены **Docker** и **Docker Compose**.

1. **Клонируйте репозиторий и создайте `.env`:**
   ```bash
   cp .env.example .env
   ```
2. **Заполните `.env`:**
   ```env
   BOT_TOKEN=your_max_bot_token_here
   BOT_NAME=ideya_fiks_128_bot
   BOT_URL=https://max.ru/ideya_fiks_128_bot

   # Опционально: для работы генеративного ИИ
   LLM_BASE_URL=https://openrouter.ai/api/v1
   LLM_API_KEY=your_api_key_here
   LLM_MODEL=deepseek/deepseek-chat
   LLM_FALLBACK_MODELS=qwen/qwen-2.5-72b-instruct
   ```
   *(Если `LLM_API_KEY` не указан, бот автоматически использует встроенный методический Fallback-модуль — проект полностью работоспособен без внешних платных ключей!)*

### Вариант А. Запуск через Docker Compose (Рекомендуемый)

```bash
# 1. Сборка и фоновый запуск контейнера:
docker compose up --build -d

# 2. Просмотр логов работы бота в реальном времени:
docker compose logs -f

# 3. Остановка контейнера:
docker compose down
```

### Вариант Б. Запуск через командную строку (Docker CLI)

Если требуется собрать образ и запустить контейнер напрямую через терминал (без Docker Compose):

```bash
# 1. Сборка Docker-образа:
docker build -t vector-max-bot:latest .

# 2. Запуск контейнера в фоне с монтированием тома данных и переменными окружения:
docker run -d \
  --name vector-max-bot \
  --restart unless-stopped \
  --env-file .env \
  -v "$(pwd)/data:/app/data" \
  vector-max-bot:latest

# 3. Просмотр логов:
docker logs -f vector-max-bot

# 4. Остановка и удаление контейнера:
docker stop vector-max-bot && docker rm vector-max-bot
```

> 💡 **Быстрый запуск готовым скриптом:**  
> В проект включен готовый bash-скрипт, выполняющий шаги сборки и запуска в одну команду:  
> ```bash
> chmod +x docker-run.sh
> ./docker-run.sh
> ```

## ⚠️ Архитектурные особенности и ограничения

1. **Готовое развёртывание решения (Zero-Setup для жюри):**
   * Бот **уже развернут на сервере и функционирует в режиме 24/7**.
   * Экспертам жюри **нет необходимости локально собирать проект или запускать Docker-контейнер** для проверки функционала. Достаточно перейти по прямой ссылке в мессенджере MAX: **[@ideya_fiks_128_bot](https://max.ru/ideya_fiks_128_bot)** и протестировать сценарии по [TESTING.md](TESTING.md).
   * Инструкции по Docker и Node.js в настоящем документе приведены для подтверждения воспроизводимости сборки и автоматизации деплоя.

2. **Особенности протокола Long Polling (Конкурентный запуск):**
   * Взаимодействие с платформой MAX Bot API реализовано по протоколу Long Polling.
   * **Ограничение протокола:** с одним уникальным `BOT_TOKEN` единовременно должен быть активен **строго один экземпляр бота**.
   * Если одновременно запустить бота на сервере и локально на компьютере с одним и тем же токеном, возникает состояние гонки соединений (*split-brain*), при котором входящие сообщения поочередно перехватываются разными процессами, нарушая пошаговый контекст диалога.
   * При необходимости локального запуска серверный инстанс должен быть временно приостановлен (либо должен использоваться отдельный тестовый токен бота).

3. **Отказоустойчивость внешних ИИ-моделей (Fallback-гарантия):**
   * Решение использует каскад моделей через OpenAI-совместимый интерфейс с жестким таймаутом 15 секунд.
   * При исчерпании квот внешних API, сетевых задержках или сбоях провайдеров бот автоматически переключается на встроенный детерминированный методический движок ФГОС. Бот гарантированно не зависает и формирует паспорт проекта и рецензию защиты в любых условиях.
